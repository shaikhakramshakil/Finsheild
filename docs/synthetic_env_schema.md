# Synthetic Digital Payment Environment — Data Contract

**Phase 4 — Finsheild**

This document is the authoritative schema reference for the synthetic environment
generated by `finsheild.synthetic_env`. **Do not casually change a schema without
updating all consumers (Phases 5–11).**

The environment produces **seven** tables:

| Table              | Rows (dev) | Purpose                                            |
|--------------------|-----------:|----------------------------------------------------|
| `users`            |     2 000 | Identity dimension                                 |
| `accounts`         |     3 000 | Financial accounts owned by users                  |
| `devices`          |     2 500 | Devices used to authenticate / transact            |
| `merchants`        |       500 | Payees                                              |
| `locations`        |       400 | Geo references                                      |
| `account_devices`  |  ~5 000   | Many-to-many account ↔ device link                  |
| `transactions`     |    50 000 | Event table — the only table carrying `label_fraud` |

Generation is deterministic given `SyntheticEnvConfig(seed=…)`.

---

## Common conventions

- IDs are 1-based contiguous `int64`.
- Timestamps are naive UTC `pd.Timestamp` (seconds precision).
- All string columns are categorical Python `str` — no `pd.Categorical`.
- `scenario_tag` is `"background"` for ordinary activity and one of the eight
  scenario names for scenario events.
- `label_fraud` is **only** `1` for the *flagged* transaction of a scenario
  episode. Context transactions and the background stream are `0`.

## `users`

| Column         | Type     | Notes                                                         |
|----------------|----------|----------------------------------------------------------------|
| `user_id`      | int64    | PK                                                              |
| `signup_ts`    | ts       | Uniform in `[start_ts − 30d, end_ts]`                           |
| `home_country` | str      | ISO-2 country code from `COUNTRIES` (10 countries)              |
| `risk_segment` | str      | One of `standard`, `premium`, `student` (weighted)             |

## `accounts`

| Column        | Type  | Notes                                                       |
|---------------|-------|--------------------------------------------------------------|
| `account_id`  | int64 | PK                                                            |
| `user_id`     | int64 | FK → `users.user_id`                                          |
| `opened_ts`   | ts    | Uniform in `[start_ts − 180d, start_ts]`                       |
| `account_type`| str   | `checking`, `savings`, or `credit`                             |
| `status`      | str   | `active` (majority), `dormant`, `closed`                       |

## `devices`

| Column           | Type  | Notes                                              |
|------------------|-------|-----------------------------------------------------|
| `device_id`      | int64 | PK                                                  |
| `device_type`    | str   | `mobile_ios`, `mobile_android`, `desktop_windows`, `desktop_macos`, `tablet` |
| `fingerprint_hash`| str  | Deterministic 16-hex string per device               |
| `first_seen_ts`  | ts    | Uniform in transaction window                       |

## `merchants`

| Column        | Type  | Notes                                                  |
|---------------|-------|---------------------------------------------------------|
| `merchant_id` | int64 | PK                                                       |
| `name`        | str   | `<category>_<5-digit index>`                              |
| `category`    | str   | One of 10 `MERCHANT_CATEGORIES`                           |
| `mcc_code`    | int   | Stable 4-digit code in `[1000, 9999]` per (cat,country)   |
| `country`     | str   | ISO-2 country                                             |
| `risk_band`   | str   | `low`, `medium`, or `high`                               |

## `locations`

| Column        | Type   | Notes                                                |
|---------------|--------|------------------------------------------------------|
| `location_id` | int64  | PK                                                   |
| `city`        | str    | Synthetic city name (no real geocoding)              |
| `country`    | str    | ISO-2                                                |
| `lat`, `lon` | float  | Deterministic synthetic coords, **not** real geocoded |
| `region`     | str    | Equals `country`                                     |

## `account_devices`

| Column         | Type  | Notes                                              |
|----------------|-------|----------------------------------------------------|
| `account_id`   | int64 | FK → `accounts.account_id`                          |
| `device_id`    | int64 | FK → `devices.device_id`                            |
| `first_used_ts`| ts    |                                                |
| `last_used_ts` | ts    |                                                |
| `is_primary`   | bool  | First device in the account's list                  |

## `transactions`

| Column         | Type   | Notes                                                        |
|----------------|--------|--------------------------------------------------------------|
| `txn_id`       | int64  | PK                                                           |
| `account_id`   | int64  | FK → `accounts.account_id`                                    |
| `device_id`    | int64  | FK → `devices.device_id` (may be a *new* device in scenario 4)|
| `merchant_id`  | int64  | FK → `merchants.merchant_id`                                  |
| `location_id`  | int64  | FK → `locations.location_id`                                  |
| `ts`           | ts     | Uniform in `[start_ts, end_ts]` with daily-hour modulation   |
| `amount`       | float  | Lognormal distribution (mean ≈ 36, σ ≈ 0.95) for background  |
| `currency`     | str    | Always `"USD"` for now                                       |
| `channel`      | str    | `online`, `pos`, `atm`, `mobile`                              |
| `status`       | str    | Always `"settled"` for now                                   |
| `scenario_tag` | str    | `background` or one of 8 scenario names                       |
| `label_fraud`  | int    | `0` or `1` — see table below                                  |
| `scenario_extra` | str  | Free-form, JSON-encoded diagnostic info from scenario         |

### `scenario_tag` and `label_fraud`

| `scenario_tag`        | `label_fraud=1` count per episode | Context rows  |
|-----------------------|----------------------------------:|--------------|
| `account_takeover`    | 1                                | 1–2 baseline |
| `unusual_amount_time` | 1                                | 1 baseline   |
| `transaction_velocity`| 8–12                             | 1 baseline   |
| `new_device`          | 1                                | 1 baseline   |
| `unusual_location`    | 1                                | 1 baseline   |
| `device_sharing`      | 1                                | 1 baseline   |
| `mule_behavior`       | 1 (large outbound)               | 4–8 inbound  |
| `unusual_merchant`    | 1                                | 1 baseline   |

The "context" rows stay `label_fraud=0` — they exist so feature engineering
later can compute velocity / baseline / device-sharing signals *around* the
flagged transaction rather than seeing an obvious `fraud=1` row in isolation.

## Configuration

```python
from finsheild.synthetic_env import SyntheticEnvConfig, generate_environment

# CI scale — small, fast
env = generate_environment(SyntheticEnvConfig.ci())

# Dev scale — production-ish
env = generate_environment(SyntheticEnvConfig.dev())

# Custom
env = generate_environment(SyntheticEnvConfig(
    seed=2025, n_users=10_000, n_transactions=200_000,
    time_span_days=60, fraud_rate=0.02,
))
```

The same config yields **byte-identical** tables.

## Leakage rules

1. **No future timestamps.** Every event timestamp is at or before `end_ts`.
2. **No label leakage from reference tables.** `users`, `accounts`, `devices`,
   `merchants`, `locations` never carry `label_fraud`.
3. **No account_devices carries a label.** Mule rings are inferred downstream
   from the link graph, not pre-flagged.
4. **`scenario_extra` is descriptive, not predictive.** It is a JSON blob
   created at generation time to make debugging easier — feature engineering
   in Phase 5+ must NOT read it.

---

## What this contract does NOT promise

- Real-world fraud distributions. The fraud rate in dev scale is around
  11% because scenarios are over-represented; this is intentional for
  training experiments.
- Geocoding correctness. `lat`, `lon` are synthetic.
- Time-of-day realism. The hourly modulation is a coarse 24-bin distribution.
